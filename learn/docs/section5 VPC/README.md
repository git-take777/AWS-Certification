- セクション5 VPC
  - サブネットの理解
  - VPCの概要
    - VPCとサブネットの関係
      - VPCがアドレス範囲を規定
        Ex. 10.0.0.0/16 (65,536このIPアドレス)
      - 最小構成: 1VPC + 1サブネット
        - 1つのVPC内に単一サブネットを配置した最小構成のネットワーク設計
          - Ex.
            - サブネット1(10.0.0.0/24)
            - Az: ap-northeast-1a
            - EC2インスタンス
            - 構成ポイント
              - 最小構成: 1VPC + 1サブネットでシンプルなネットワーク環境を構築
              - Az配置
              - 拡張性: 必要に応じてサブネットを追加可能
        - 複数Az構成 (高可用性)
          - Az分散メリット
            - 可用性向上: 複数Azに分散配置することで、単一障害てんを排除
          - 耐障害性: AZ障害時も他AZで計測稼働
          - 低レイテンシ: 同一AZ内で高速通信
        - デフォルトVPC
          - デフォルトVPCの基本設定
            - 各リージョンに1つのデフォルトVPCを自動作成
            - 最大 65536個のプライベートIpv4アドレスを提供
            - 各AZに20のデフォルトサブネットを作成
          - 自動付与されるリソース
            - インターネットゲートウェイを作成してVPCに接続
            - デフォルトのセキュリティグループを作成・関連付け
            - デフォルトのネットワークACLを作成・関連付け
            - デフォルトDHCPのオプションセットを関連付け
              ⇨これでユーザーはネットワーク設定を意識することなく、EC2を起動してインターネットに自動で接続できる
          - DNS設定
            - パブリックDNSホスト名を付与可能
            - プライベートDNSホスト名も利用可能
    - サブネット
      - サブネットはCIDRで分割したVPCのネットワークセグメント
      - サブネットを分割する理由
        - 用途に合わせてネットワークを分割しセキュリティを高めるため
        - Publicサブネット vs Privateサブネット
        - 通信制御のルールを持つことで安全に通信できる環境を構築できる
        - ルートテーブル設定
          - 最長一致ルーティング
            - 経路選択: 宛先IPと最長一致するルート
            - 優先順位: より具体的なCIDRが優先される
            - 複数経路: 複数ルートが存在する場合、最長一致で決定
      - サブネットによる構成
        - 公開系
          - 外部公開が必要なwebサーバーを配置
          - 認証認可サーバー: 外部からのアクセスを制御する認証系
        - 非公開系
          - DB/RDS セキュリティを高めたいデータベースを配置
          - アプリケーションサーバー
          - 内部監視・ログサーバー
      - NatGateway
        - 役割:
          - privateサブネットからの外向き通信をNAT GWに転送
          - NAT GWでプライベートIP⇨パブリックIPに変換
          - インターネットへアクセスし、レスポンスを返送
