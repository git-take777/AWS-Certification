- セクション3 AWSの概要
  - 仮想化を理解する
  - 仮想化とは、1つのサーバーを複数のサーバーに見せかけること
    - 1つのサーバーの中に VM1,VM2,VM3,VM4とかそうサーバーを建てることができる
  - 仮想化のメリットがある。(後述)
  - 仮想化タイプ
    - 分割、集約、模倣
      - 分割: 1台の物理リソースを複数に分割する技術。
      - 集約: 複数の物理リソースを1つに主役する技術、複数のストレージを統合して1つの大きなストレージを構成する
      - 模倣: ある物理リソースを別の物理リソースに見せかける技術。
      - リソースの可変割り当てとスケーリング
- サーバー仮想化の4つの対象領域
  - サーバー仮想化
  - ストレージ仮想化
    - ブロックレベル仮想化
      - 複数のストレーズを仮想的に統合し、1つの大きなストレージを構成。物理的な制約を超えた柔軟な要領管理が可能。

    - ファイルレベル仮想化
      - ファイルシステムを抽象化し、複数のストレージデバイスを統合。デー屋の移動や複製を投下的に行う。
        ※ 需要に応じて、ストレージ容量を動的に拡張。コスト効率とパフォーマンスの最適化を実現。

  - ネットワーク仮想化
    - SDN・・・ソフトウェアによるネットワークを制御。物理的なネットワークの設定を自動化。
    - VLAN・・論理的なネットワークセグメントを作成。セキュリティとトラフィック管理を強化。
  - 仮想化のメリット
    - コスト最適
    - 導入迅速化
    - 柔軟性
    - セキュリティ

  - クラウド基礎
    - AWSサービスの概要
      - Ec2・・・仮想サーバー。
        - 機能
          - インスタンスタイプ・・・CPU、メモリ、ストレージを選択可能
          - EBS・・永続的なストレージ
          - セキュリティグループ
            - ファイアーウｵール機能で保護
          - パブリック/プライベートIP
            - 柔軟なネットワーク設定
      - ELB
        - EC2サーバーを複数に増やし負荷分散し、あ矯正や拡張性が可能
        - 将来的に自動的に行う Autoスケーリングできる
        - セキュリティ SSL/TLS終端をサポート

    - AWSのグローバルインフラ構成
      - リージョン
        - データセンターが集約されている世界中の物理的ロケーションを指す。
        - リージョンに応じて、利用可能なサービスが異なる
        - リージョンとリージョンは物理的に独立したインフラ拠点
        - 独自性の特徴
        - 物理的分離
        - 運用的独立
        - ネットワーク分離
        - セキュリティ確保
      - AZ
        - 1つのAWSリージョン内でそれぞれ切り離され、冗長的な電力源、ネットワーク、接続情報を備えている1つ以上のデータセンターです。

    - AWSサービスの全体像1
      - 初め
        - クラウドプラクティショナーとソリューションアーキテクトに必要なサービスを網羅的に覚える
        - ジャンル別に把握してサービスの違いを比較
        - 最適なサービスを選択する問題に回答できるようにする
        - 動画視聴なしでもレクチャー資料をサービスリストとして学習可能
      - コンピューティング
        - EC2:仮想サーバー
          柔軟性と制御 EC2は高いカスタマイズ性を持ち、様々なOSやミドルウェアを構成可能
        - AmazonLightSailitems差そうサーバーストレージなどの構成を低価格で提供
          - シンプルで予測可能な料金体系で、小規模プロジェクトに最適
        - Lambda:サーバーれsettingsでコードを実行するサービス
          - サーバー管理が不要で、開発に集中できる
        - Fargate: コンテナ向けのサーバーレスコンピューティング
        - VMware Cloud on AWS
          - VMwareアーキテクチャをクラウド上で実現
          - ハイブリット環境: 既存尾のオンプレとシームレスに連携
        - Aws Auto Scaling
          - EC2: Auto Scaling グループ内でインスタンスを起動または終了する
          - ECS: 負荷の変動に合わせて、ECSサービスの必要数を調整する
          - DynamoDB/AUrora: トラフィックの急激な増加に対応
        - AWS Serverless Application Repository
          - サーバーレスApplication用のマネジ度型リポジトリ
          - IAMによる権限管理によって、チーム、組織、開発者個人が再利用可能なアプリケーションを保存して共有できる

        - 特殊な要件や配置

      - ネットワーキングとコンテンツ配信
        - ネットワークの基本サービス
          - VPC
            - 仮想ネットワーキング環境を構築するサービス
          - Route53
            - ドメイン登録とルーティングを実施する
          - ELB
            - EC2インスタンスなどのトラフィック制御を実施するロードバランサーサービス
        - コンテンツ配信と最適化
          - CDN
            - エッジロケーションを利用して、低レイテンシーかつ高速なデータ転送により世界中にっコンテンツを配信するネットワークサービス
          - Global Acclerator
            - エッジロケーションを利用してアプリケーションへのユーザートラフィックのパフォーマンスを最大60%向上させるネットワーキングサービス
        - 接続(プライベート/グローバル)
          - AWS Direct Connect: AWSとデータセンターやオフィスとのアイ第二プライベート接続を確立する専用線サービス。
          - AWS サイト間VPN: データセンターまたはオフィスとAWS間の安全な接続を実施。
          - WS Client VPN: ユーザー需要に合わせて自動的にスケール。フルマネージド型で伸縮自在なVPNサービス。
          - Cloud WAN: クラウドとオンプレ環境のリソース間で実行されるトラフィックを管理、リージョン間のグローバルネットワークを自動作成
        - 集約とプライベートアクセス
          - Trabsut Gateway
            - VPNとオンプレネットワークを接続する中央ハブとなるクラウドルーター。複数VPCやオフィス間の複雑なルーティングを簡素化し、大規模なネットワーク構築を容易にする
          - PrivateLink
            - データをインターネットに公開せず、VPCとAWSでホストされているサービス。
